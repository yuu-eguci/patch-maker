## ベースライン (2026-10-08 調査)

- 構成は `PatchMaker.py` 1 ファイルのみです。依存ライブラリはありません。
- ローカルの Python 3.9.6 で、 README どおりの使い方 (冒頭の `targetpaths` を書き換えて実行) で動作しました。
- テスト、 lint 、 CI 、 Docker はありません。
- 確認した問題点です。パッチ名の決定時期以外は、下の進捗のバッチで解消済みです。
    - `../secret.txt` を指定すると、パッチディレクトリの外 (スクリプトと同じディレクトリ) へコピーされます。既存ファイルを上書きする可能性があります。
    - 行は `\n` だけで分割されます。行末の空白や `\r` (CRLF) が残り、存在するファイルが「見つからない」扱いになります。
    - 対象パスは `set()` を通るため、コピー順が不定です。ディレクトリ `d` と `d/f.txt` を同時に指定すると、順序次第で `FileExistsError` になります。
    - パッチ名 `PATCHNAME` はモジュール読み込み時に決まります。 1 回の実行で 1 つのパッチを作る使い方では問題にならないため、維持しています。
    - 絶対パスは `<パッチ名>//絶対パス` となり、偶然パッチ内に収まっています。

## 残課題

- 読み取り専用のコピーを削除するテストは root 以外で実行したときだけ動きます。 Docker では `--user 1000:1000 -e HOME=/tmp` を付けて `pytest -p no:cacheprovider` で確認しています。
- 大文字と小文字の区別に関するテストは、区別するファイルシステム (Linux の CI など) ではスキップされます。 macOS では `--basetemp` に macOS のディレクトリを指定し、 Docker からマウントして確認しています。
- Docker のベースイメージはダイジェストで固定しています。セキュリティ更新を取り込むときは、ダイジェストを手動で更新します。
- 見つからないパスが 0 件でも `[]` と件数を表示します。ベースラインの出力形式を維持しています。
- Windows のジャンクション除外 (`os.path.isjunction`) は Windows 実機で未検証です。
